# Fonotext — речевая аналитика телефонных разговоров

**Разбор 100 % звонков: транскрипты со спикерами, классификация каждого разговора,
контроль скриптов с доказательствами и дашборды для руководства.**

🌐 Сайт: **https://fonotext.ru/** ·
📊 Демо-стенд: [local-poc](local-poc/README.md) ·
🖥 Демо-панель: [docs/demo/](docs/demo/index.html) ·
📄 Презентация: [docs/00](docs/00-product-presentation.md)

Платформа превращает записи звонков (стерео: клиент и оператор в разных каналах) в
структурированные данные: транскрипт с таймкодами на уровне слов, классификация
каждого звонка (живой разговор, автоответчик, спам-блокировка, робот, без ответа; результат,
теги, соблюдение скрипта), метрики разговора и готовые дашборды — с задержкой в минуты,
а не в дни.

Продукт рассчитан на крупные контакт-центры и аутсорсеров (100–500+ операторов) с
требованиями к контуру обработки данных. Коммерческие условия и тарифы на сайте
не публикуются — обсуждаются на пилоте.

| | Как обычно | Fonotext |
|---|---|---|
| Покрытие звонков | 3 % (выборка ОКК) | **100 %**, включая «неудобные» |
| Задержка отчётов | дни–недели | минуты (SLA ≤ 24 ч) |
| Исторический архив | не разбирается никогда | партиями: 450 тыс. часов ≈ 6–12 недель |
| Спор «я это говорил» | переслушивание записи | цитата + таймкод + канал спикера |
| Смена таксономии | повторный прогон и бюджет | переклассификация **без** повторного распознавания |
| Контур данных | облако или «своя стойка» | облако в РФ, выделенный шард или on-prem |

## Возможности

- **Транскрибация** русского языка с таймкодами на уровне слов; спикеры определяются
  физически по каналам записи — без нейросетевой диаризации и её ошибок.
- **Классификация каждого звонка:** тип соединения, результат, теги, соблюдение скрипта,
  конфликтность. Каскад «правила → LLM → человек»; низкая уверенность уходит в очередь
  ручного контроля. Таксономия настраивается без релиза.
- **Контроль скриптов с доказательствами:** каждое нарушение подтверждено цитатой,
  таймкодом и каналом; оператор может оспорить, спорный звонок уходит в ручной разбор.
- **Переклассификация без повторного ASR:** смена таксономии пересчитывает вердикты по
  сохранённым транскриптам за часы.
- **Архив «под ключ»:** отдельный конвейер для накопленных записей — инвентаризация,
  дашборд прогресса с ETA, итоговый отчёт с примерами звонков.
- **Интеграции:** коннекторы к Битрикс24, amoCRM, Salesforce, Asterisk и 3CX, вебхуки в
  Telegram, Slack и MS Teams, REST API с HMAC-подписью.
- **LLM-аналитик:** вопрос к базе разговоров обычными словами — с ответом, цифрами и
  ссылками на конкретные звонки.
- **Метрики разговора:** talk ratio, перебивания, паузы, длительность.

## Контур и безопасность

- **Три сценария поставки:** облако в РФ, выделенный шард с изоляцией (свои ключи BYOK,
  приватный канал), коробка on-prem на мощностях заказчика.
- **152-ФЗ:** роли оператора и обработчика ПДн фиксируются в договоре; данные не покидают РФ.
- **Доступ:** ролевая модель, SSO/AD, журнал доступа к транскриптам, маскирование номеров
  и ПДн в выгрузках.
- **Качество:** замер WER на записях заказчика в пилоте, регресс-набор и ежемесячный отчёт
  «обещали / получили» с расхождением не более 1 п.п.

## Как мы работаем с новым заказчиком

1. **Анкета интеграции** ([docs/01-integration.md](docs/01-integration.md)) — 20 минут: как
   хранятся записи, форматы, объёмы, требования к контуру.
2. **Пилот 2–4 недели** ([docs/05-poc-plan.md](docs/05-poc-plan.md)): эталонная разметка
   60–90 минут аудио + 300–500 звонков, сравнение 3–4 моделей ASR, критерии Go/No-Go
   согласованы заранее. Мы не обещаем «волшебный WER» — мы его измеряем и подписываемся цифрами.
3. **Поставка 4–8 недель** (коробка) или 1–2 недели (облако, приватный контур).
