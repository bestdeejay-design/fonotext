# T1b — бенч 4 параллельных воркеров (исправление T1)

Дата: 2026-11-01, стенд B (IT-AI-Test2, 10.10.0.98). Модель qwen3:4b-instruct.
База сравнения: T1 (протокол T1 хранится на стенде B: `/home/badai/t1_protocol.md`;
в этом репозитории каталога `protocols/` до этого коммита не было).

## Суть теста
T1: бенш одним потоком → 56,8 зв/ч, 3 из 4 слотов простаивали, парсер извлёк 0 items.
T1b: те же условия + **4 параллельных воркера** (`concurrent.futures.ThreadPoolExecutor(4)`
поверх urllib), 40 звонков (страта T1: 16 средних 2000–5000 зн. + 24 коротких <2000),
исправленный парсер, динамический JSONL.

## Подготовка
- `fonotext-ollama-bulk` (порт 11435) поднят; изоляция с T1 на месте
  (drop-in `/etc/systemd/system/fonotext-ollama-bulk.service.d/t1-local.conf`,
  `OLLAMA_HOST=127.0.0.1:11435`); чужого трафика с 10.10.0.99 нет (`ss -tn` чисто,
  бенч гонялся локально на B).
- `OLLAMA_NUM_PARALLEL=4` (был в юните с T1), `OLLAMA_MAX_LOADED_MODELS=1`, keep_alive -1.
- Прогрев qwen3:4b-instruct: `ollama ps` = 100% GPU, 5,1 ГиБ при ctx 4096.

## Диагностика парсера (корень отказа T1)
1. В T1-скрипте в запросе не было `format`-схемы (в протоколе T1 заявлена — фактически
   отсутствовала): модель отвечала без гарантированного JSON, а ответ обрезался лимитом
   генерации → `extract` давал 0 items на всех 25 звонках.
2. Отладка на 1 звонке: с `format`-схемой модель возвращает чистый JSON в
   `message.content` (без markdown-обрамления, без `<think>`).
3. Вторая находка: `num_predict: 4096` при полном промпте (system 54 пункта +
   транскрипт ≈ 2700–3200 prompt-токенов) обрезал JSON → парс падал. После поднятия
   `num_predict` до 6144 и `num_ctx` до 8192 — 40/40 ответов strict-парсятся.
4. Модель иногда дублирует пункты (n_raw до 100, id до 86): парсер дедуплицирует по id
   (первое вхождение, диапазон 1–54) — во всех 40 ответах ровно 54 items.

## Исправления T1b-скрипта
- `format`: схема checklist в каждом запросе;
- `options`: `num_predict 6144`, `num_ctx 8192`, `temperature 0.1`;
- парсер: strict `json.loads` → срез ```-забора → regex `{.*}` → посимвольный salvage
  обрезанного JSON; дедупликация id 1–54;
- `ThreadPoolExecutor(4)`, аппенд JSONL под локом, `ts_epoch` в каждой строке.
