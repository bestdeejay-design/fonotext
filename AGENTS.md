# AGENTS.md — правила для агентов в этом репозитории

<!-- boundaries-allow: bom, procurement, internal-finance, cost-basis, margin -->

> Этот репозиторий — **публичный продукт Fonotext** (сайт на GitHub Pages из каталога `docs/`).
> Второй репозиторий проекта — приватный (закрытый контур): там требования, экономика,
> финансовая модель и канон цифр. Полные правила — `governance/RULES.md` закрытого контура.

## 1. Главное в трёх строках

- **Стратегия** (бизнес-требования, тарифы, скидки, планы, финансовая и бизнес-модель, канон цифр)
  формируется в приватном репозитории. Здесь эти решения только **исполняются**.
- **Ты — исполнитель:** исследование, проверка, подготовка, публикация одобренного, отчёты.
  Предлагать варианты можно; выбирать — нет.
- Любая цифра, которой нет в утверждённом каноне, — повод остановиться и оформить заявку,
  а не «дописать для консистентности».

## 2. Жёсткие запреты

1. **Не менять цифры:** цены, тарифы, скидки, условия, SLA, объёмы, сроки в коммерческих
   документах. Правка формулировок без изменения цифр — можно.
2. **Не публиковать внутреннее:** маржу, себестоимость, burn, выручку/ARR, закупочные цены,
   BOM, «прайс-гардрейлы», внутренние ссылки и имена файлов приватного репозитория.
3. **Не публиковать** имя, отрасль и бюджет конкретного заказчика (в обезличенном виде — только
   в инвесторском разделе, если это одобрено).
4. **Не выводить инвесторский раздел** (`docs/investors/`) в навигацию, каталог документации,
   `sitemap.xml`, `llms.txt`; не снимать с него `noindex`.
5. **Не переносить** файлы из приватного репозитория напрямую — только из пакета `handoff/*`,
   который прошёл проверку.

## 3. Перед любой публикацией

Скопировать файлы чекера и конфигурацию из приватного репозитория (разово) и запускать:

```bash
python3 tools/check-boundaries.py docs README.md --profile public

# для инвесторского раздела
python3 tools/check-boundaries.py docs/investors --profile investor
python3 tools/site-audit.py         # технический аудит сайта: 0 критичных, 0 предупреждений
```

Ненулевой код возврата чекера = публикация запрещена. Разбор вывода — в `governance/RULES.md` §8
приватного репозитория: НАРУШЕНИЯ блокируют, предупреждения разбираются поштучно, «цифры
к проверке» — это повестка сверки с каноном (не угадывать!).

## 4. Если чего-то не хватает

- Нужна цифра/тариф/срок/разрешение на публикацию → **заявка** по шаблону
  `governance/templates/REQUEST.md`; заявка передаётся в закрытый контур, задача переводится
  в `ЖДЁТ РЕШЕНИЯ`, работа продолжается на незаблокированной части.
- Нашёл утечку или расхождение → **новая задача** (не правь «заодно» то, что не входит в задание).

## 5. Что можно решать самостоятельно

Технические и редакционные вопросы без изменения смысла и цифр: SEO, перелинковка, доступность,
структура страниц, оформление HTML, исправление опечаток, генерация документации, техдолг
инструментов, ошибки в ссылках.

## 6. Текущее задание

задание по публикациям из закрытого контура: аудит утечек → сверка прайсов → публикация
инвесторского раздела и двух публичных страниц. Порядок обязателен; шаг 2 (решение владельца
по ценам) — блокирующий.
