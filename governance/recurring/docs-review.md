# Регулярная ревизия документации

- **Ритм:** 1-е число каждого месяца, 09:00 МСК (cron `docs-review.yml`), плюс ручной запуск.
- **Задача:** issue с метками `docs-review`, `role:audit` — её видно на доске Projects.
- **Исполнитель:** любой агент с ролью аудитора; координатор принимает итог.
- **Правила:** `governance/DOCS.md`. Индекс: `governance/DOCS-INDEX.md`.

## Зачем

Документы стареют быстрее, чем их правят. Эта задача — единственное место, где старение
разбирается системно: раз в месяц, по чек-листу, с записью результата. Всё, что не
разобрано здесь, превращается в мусор, по которому кто-то примет неверное решение.

## Порядок работы

1. Прочитать `governance/DOCS.md` §3 и §7 (жизненный цикл и ритм ревизии).
2. Прогнать проверки и приложить вывод в комментарий к задаче.
3. Пройти чек-лист ниже. Каждый пункт закрывается **либо правкой, либо новой задачей**
   со ссылкой. «Оставил как есть» — не результат.
4. Обновить индекс (`--index`) и закоммитить, если что-то менялось.
5. Итог — комментарий с числами и ссылками, затем закрыть задачу.

```bash
python3 tools/docs-registry.py --check --strict
python3 tools/docs-registry.py --check-index
python3 tools/check-boundaries.py docs README.md --profile public
python3 tools/site-audit.py
```

## Чек-лист

### 1. Реестр и индекс

- [ ] `--check` без нарушений; каждое предупреждение разобрано или заведена задача.
- [ ] Все документы, появившиеся за месяц, зарегистрированы (тип, владелец, статус).
- [ ] `DOCS-INDEX.md` пересобран и совпадает с реестром (`--check-index`).
- [ ] Ни один документ не живёт «на диске»: всё, что имеет ценность, в git.

### 2. Актуальность

- [ ] Раздел «Просрочили ревизию» в индексе пуст или по каждому пункту есть решение.
- [ ] Документы, описывающие то, чего в продукте нет, переведены в `deprecated` с заменой.
- [ ] Новые релизы и изменения продукта отражены в спецификациях и на страницах сайта.

### 3. Артефакты

- [ ] У каждого нового артефакта есть шапка (`type`, `date`, `status`, `owner`, `contour`).
- [ ] Артефакты старше 120 дней: выводы перепроверены или помечены устаревшими.
- [ ] Артефакты с внутренними данными не попали в публичный контур.
- [ ] Дубли по заголовкам сведены: один остаётся, второй помечается заменённым.

### 4. Чистота зон

- [ ] В корне нет отчётов, черновиков и рабочих файлов.
- [ ] `docs/` содержит только публикуемое; страницы-заглушки помечены `tombstone`.
- [ ] В `governance/` нет отчётов и ресёрчей — только правила, реестр, шаблоны, задачи.
- [ ] `artifacts/` не содержит файлов без шапки.
- [ ] `.gitignore` не скрывает от git ничего, что является документом.

### 5. Границы и публикация

- [ ] `check-boundaries.py --profile public` — 0 нарушений.
- [ ] `site-audit.py` — 0 критичных, 0 предупреждений.
- [ ] Инвесторский раздел (если есть) не выведен в навигацию, `sitemap.xml` и `llms.txt`.

### 6. Итог

- [ ] Числа в комментарии: документов, артефактов, устаревших, просроченных, новых задач.
- [ ] Задачи на исправления созданы и назначены (или эскалированы координатору).
- [ ] Запись о решениях, меняющих правила, — в журнале решений закрытого контура.

## Шаблон итога

```markdown
**Ревизия за <месяц>**

- Документов: N (актуальных N, устаревших N, просрочили ревизию N)
- Артефактов: N (новых за месяц N, помечено устаревшими N)
- Исправлено в этом проходе: <список>
- Заведено задач: #NN, #NN
- Эскалировано координатору: <что и почему>
```

## Чего эта задача не делает

- Не меняет цены, тарифы, коммерческие условия и цифры — это заявка в закрытый контур.
- Не удаляет документы: только переводит в `deprecated`/`archived` с заменой.
- Не переписывает содержание «для консистентности»: правка смысла — отдельная задача.
- Не трогает чужие зоны без записи в задаче.
