# Шаблон артефакта — ресёрч, аудит, отчёт, выводы

> Копируется командой `python3 tools/docs-registry.py --new research "короткое-имя"`
> или вручную. Артефакт без шапки не принимается: `tools/docs-registry.py --check`
> считает это нарушением. Правила — `governance/DOCS.md` §4.

## Что такое артефакт

Документ, который отвечает на вопрос и приводит доказательства: ресёрч, аудит,
разбор инцидента, отчёт о замере, пакет передачи. У него есть автор, дата и срок
жизни. Он не «страница сайта» и не «регламент»: его не публикуют, на него ссылаются.

## Обязательная шапка

Ставится первой строкой файла, до заголовка H1. В отрендеренном виде не видна,
читается скриптами:

```markdown
<!-- artifact
type: research
date: 2026-11-02
status: active
owner: research
contour: public
review_after: 2027-05-01
sources: docs/02-architecture.md, docs/03-models.md
-->

# Заголовок артефакта
```

| Поле | Обязательно | Значения |
|---|---|---|
| `type` | да | `research`, `audit`, `report`, `decision`, `handoff` |
| `date` | да | дата работы, `ГГГГ-ММ-ДД` — по ней считается старение |
| `status` | да | `active`, `superseded`, `archived` |
| `owner` | да | `product`, `tech`, `governance`, `research` |
| `contour` | да | `public` — можно публиковать; `private` — только закрытый контур |
| `review_after` | желательно | дата, после которой выводы надо перепроверить (по умолчанию +180 дней) |
| `sources` | желательно | что читали: пути или URL |
| `superseded_by` | при устаревании | путь или URL документа, который заменил этот |

## Обязательный баннер при устаревании

Если `status: superseded` или `archived`, сразу после шапки ставится видимая строка —
иначе читатель не узнает, что выводы отменены:

```markdown
> ⚠️ **Устарело** (2027-02-01). Замена: `artifacts/research/2027-01-20-новый-разбор.md`.
```

Перевод в устаревшие — командой, а не вручную:

```bash
python3 tools/docs-registry.py --deprecate artifacts/research/2026-11-02-имя.md \
    --by artifacts/research/2027-01-20-новый-разбор.md
```

## Структура (работает для всех типов)

```markdown
# <Что выясняли — одной строкой>

## Вопрос
<Зачем этот артефакт существует. Что было неясно.>

## Что проверено
| Источник | Что взято | Дата проверки |
|---|---|---|

## Выводы
<Только то, что подтверждается источниками. Непроверенное — «не знаю», а не догадка.>

## Что делать
<Следствия: что меняем, что не меняем, что уходит в заявку REQUEST.>

## Что не проверено
<Границы работы: где доказательств нет.>

## Источники
<Полные пути и URL.>
```

## Правила, которые проверяет скрипт

1. Шапка есть и заполнена (иначе — нарушение).
2. `date` в формате `ГГГГ-ММ-ДД`.
3. `status` из допустимого набора.
4. При `superseded`/`archived` указан `superseded_by` и есть баннер.
5. Артефакт старше `stale_artifact_days` (120 дней) — предупреждение «проверь выводы».
6. Дубли по заголовку — предупреждение.

## Куда класть

| Контур | Куда | Что можно |
|---|---|---|
| Публичный | `artifacts/research/`, `artifacts/audit/`, `artifacts/reports/` | только то, что прошло `check-boundaries.py` |
| Закрытый | зоны артефактов закрытого контура | всё внутреннее: цены, поставщики, заказчики |

Правило владельца: артефакт живёт **в GitHub**, а не на диске. Локальный файл,
на который ссылаются из задач и документов, — потерянная работа: его не найдут
ни агенты, ни человек через месяц.
