# Локальный стенд (local-poc) — проверка работоспособности на MacBook

Мини-копия прод-пайплайна из [docs/02-architecture.md](../docs/02-architecture.md), работающая
на одной машине без GPU. Проверяет **правильность механики** (каналы → ASR → слияние → метрики →
классификация), а не пропускную способность — скорость на ноутбуке не экстраполируется на прод
напрямую, для этого есть расчёт в [docs/04-hardware.md](../docs/04-hardware.md).

## Состав

| Файл | Что делает |
|---|---|
| `make_test_calls.sh` | Синтезирует 3 тестовых стерео-звонка (TTS macOS Milena + ffmpeg): живой разговор, автоответчик, спам-блокировщик. Левый канал = клиент, правый = оператор — как у заказчика |
| `pipeline.py` | Пайплайн: разделение каналов → ASR (faster-whisper **large-v3-turbo int8 ≈ 810 МБ**) → слияние реплик по таймкодам → метрики (talk ratio, перебивания) → классификация правилами → JSON в `out/` |

## Запуск

```bash
cd local-poc
./make_test_calls.sh                      # сгенерировать тестовые звонки (нужен macOS с голосом Milena)
python3 -m venv .venv && .venv/bin/pip install faster-whisper numpy
.venv/bin/python pipeline.py              # при первом запуске скачает модель ~810 МБ
```

Требования: macOS (для синтеза тестов), ffmpeg, ~1 ГБ диска под модель, 8+ ГБ RAM.
На другом железе можно положить свои стерео-WAV в `test_data/` и запускать `pipeline.py`.

## Что стенд уже поймал (и почему такие прогоны нужны)

1. **Галлюцинации Whisper на тишине**: на пустом хвосте звонка модель уверенно дописывала
   «Продолжение следует…» и портила talk ratio (43 с «речи» клиента в 16-секундном файле).
   Лечение: `condition_on_previous_text=False` + фильтр сегментов (`no_speech_prob`,
   `avg_logprob`, чёрный список фраз, обрезка по длительности файла) — реализовано в `pipeline.py`.
   В проде это останется обязательным слоем постобработки.
2. **Автоответчик ≠ «говорил один человек»**: оператор тоже говорит в автоответчик
   («Алло? Не слышу вас»), поэтому детект по односторонности речи ошибался. Правильно искать
   фразы автоответчика в **канале клиента** — исправлено, работает.
3. **Несовместимость faster-whisper × PyAV≥14** (`metadata_errors` убрали из API) на свежем
   Python 3.14: обходим, отдавая модели raw-PCM из ffmpeg через numpy (см. `load_pcm`).

## Ограничения стенда (что он НЕ доказывает)

- **Качество на реальной телефонии.** Milena — чистая синтетика; живые звонки (8 кГц, шумы,
  эмоции, перебивки, сленг) дадут заметно выше WER. Это проверяется только на записях
  заказчика — план в [docs/05-poc-plan.md](../docs/05-poc-plan.md).
- **Пропускная способность.** RTF ~3–4 на CPU ноутбука (аудио обрабатывается в ~3–4 раза
  дольше своей длительности). 450 тыс. часов на ноутбуке заняли бы ~190 лет. На одной карте
  L40S ожидаем RTF ≈ 0.013–0.025 (в ~150–300 раз быстрее ноутбука), с батчингом — ещё выше.
- **Классификация — только правила.** LLM-уровень каскада (результат звонка, скрипты, конфликт)
  добавляется в прод-версии; здесь показан принцип детекции типовых кейсов.
- Подсчёт перебиваний — упрощённый (по пересечению сегментов), для демо.
