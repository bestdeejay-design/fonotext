## 3. Архитектура сайта и приоритеты

**Проблема, требующая решения.** Сейчас `docs/` — это набор markdown-файлов, которые GitHub
Pages отдаёт как **обычный текст с Content-Type text/plain**. Поисковики их индексируют, но
пользователь видит простыню, а не страницу: нет навигации, нет CTA. Для поискового трафика
нужны HTML-страницы.

**Порядок работ:**

1. **Сейчас:** главная (индексируется, CTA, калькулятор) + markdown-документы (для тех, кто
   дойдёт, и для AI-краулеров — они читают текст).
2. **Спринт 1 (1–2 недели):** 4 HTML-страницы под кластер A:
   `/rechevaya-analitika/`, `/analiz-zvonkov-otdela-prodazh/`, `/kontrol-scriptov/`,
   `/razbor-arhiva-zvonkov/`. Каждая — 800–1200 слов, свой `<title>`, FAQ-блок с JSON-LD,
   форма заявки, перелинковка с главной.
3. **Спринт 2:** 3 сравнительные страницы: «Fonotext vs SpeechSense», «vs Rechka»,
   «vs модуль в телефонии» — с честными таблицами (уже готовы данные).
4. **Спринт 3:** блог 2 поста/месяц по кластеру C + перелинковка.

**Технические требования к новым страницам** (проходят `site-audit.py`):
уникальные title ≤ 60 и description 120–160 символов, один h1, иерархия без перескоков,
canonical, OG-картинка (можно переиспользовать тематические из `docs/social/`),
JSON-LD под тип страницы, `<main>`, alt у изображений, вес HTML ≤ 100 КБ.

## 8. Технические ограничения, о которых надо знать

- **GitHub Pages**: нет серверных редиректов и заголовков (нет `X-Robots-Tag`, нет HTTP/2 push,
  нет сжатия Brotli, `Cache-Control` фиксированный). Для серьёзной органики нужен свой домен:
  `fonotext.ru` + DNS к Pages (тогда canonical, og:url и sitemap переписать на домен).
- **Markdown как text/plain** — поисковики индексируют, но Google может помечать как
  «не HTML». Именно поэтому основной трафик должен идти на HTML-страницы (раздел 3).
- **Один домен — один язык**: `lang="ru"` стоит, `hreflang` не нужен, пока нет других языков.
- **После появления домена**: 301 со старого адреса Pages (через `CNAME` + редиректы в JS и
  canonical), перевыпуск sitemap, обновление OG-ссылок.

## 9.2. Светлая и тёмная тема (03.10.2026)

На всех страницах есть переключатель темы — одна кнопка в шапке (луна/солнце) и в шапке
каждого документа. Что важно при поддержке:

| Решение | Зачем |
|---|---|
| Выбор темы применяется inline-скриптом до отрисовки стилей | нет «вспышки» белого экрана при загрузке |
| По умолчанию — `prefers-color-scheme` пользователя | тем, у кого система тёмная, сайт сразу открывается тёмным |
| Выбор запоминается в `localStorage` (`fonotext-theme`) | возврат на сайт в прежней теме |
| `theme-color` меняется вместе с темой | панель браузера на мобильных совпадает с фоном |
| Тёмная палитра проверена по WCAG AA | контраст текста 11–16:1, приглушённого 7,4:1 |
| В светлой теме зелёный `--ok` затемнён до `#047857` | было 3,39:1 (ниже нормы), стало 5,48:1 |

Тёмная тема — не инверсия: фон `#0B0F17` (не чёрный), текст `#E7ECF7` (не белый), акцент
осветлён до `#8B93FF`, чтобы ссылки читались. Цвета задаются переменными в `:root` и
`[data-theme=dark]` — новую поверхность достаточно описать одной переменной, а не править
разметку.

**Левое меню в документации.** Меню разделов больше не «дёргается»: `position:sticky` перенесён
с внутреннего блока на сам `<aside>` и ограничен высотой экрана (`max-height:calc(100vh - 100px)`
с собственной прокруткой). Раньше sticky висел на элементе без запаса по высоте — меню
проскакивало и уезжало вместе со страницей. Дополнительно: текущий раздел подсвечивается
(скроллспай, `aria-current`), у заголовков `scroll-margin-top:86px` — при переходе по ссылке
заголовок не прячется под липкую шапку.
