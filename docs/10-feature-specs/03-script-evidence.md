# 03. Контроль скриптов с доказательной базой

| | |
|---|---|
| **Статус** | v1.1 (Q2 2027), правила — в MVP |
| **Тариф** | «Бизнес» и выше |
| **Зависимости** | [03-models.md](../03-models.md) §3.1 (уровни 0–2), [08-api.md](../08-api.md) (`classification.script_compliance`) |

## Проблема

Контроль скрипта сегодня — это либо «выборочно послушали», либо галочка в чек-листе, которую
ставит сам оператор или его руководитель. Спор «я это говорил» решается прослушиванием, то
есть никак: у руководителя группы нет времени искать фразу в 200 записях.

Отсюда две боли: **недоверие операторов** («система придирается») и **отсутствие фактов у
руководителя** («в отчёте 78 %, а почему — непонятно»).

## Решение

Каждое срабатывание правила скрипта подтверждается **доказательством**: точной цитатой,
таймкодом, каналом (оператор/клиент) и уверенностью. Никаких «просто галочек».

**Типы правил:**
- **Обязательные** (приветствие, представление, уточнение потребности, фиксация следующего
  шага) — с дедлайном: «приветствие должно быть в первых 15 секундах».
- **Запрещённые** (стоп-слова, оценочные суждения, обещания без основания).
- **Временные** (не молчать дольше 20 секунд, не перебивать клиента больше N раз) — считаются
  по метрикам перебиваний и пауз.

**Что видно по каждому нарушению:**
```
greeting        ❌ не выполнено (0–15 с)      канал оператора, речи нет
no_profanity    ✅ выполнено
next_step       ✅ «давайте я запишу вас на четверг, 15:00»
hold_ok         ❌ пауза 47 с без предупреждения
```
Плюс ссылка на карточку звонка: плеер открывается на нужном таймкоде, цитата подсвечена.

**Разрешение споров.** Оператор может оспорить нарушение в один клик; звонок уходит в очередь
ручного контроля, где руководитель фиксирует решение. Спорные случаи автоматически попадают
в регресс-набор — правила дообучаются на них (это и есть human-in-the-loop).

## Как это выглядит

- **Дашборд «Соблюдение скрипта»:** по операторам, группам, кампаниям; отдельно — динамика
  («приветствие 96 % → 99 % за месяц»).
- **Карточка звонка:** нарушения отмечены на таймлайне, рядом с плеером.
- **API:** `classification.script_compliance[] = {rule, passed, evidence, at}` —
  можно забирать в CRM или в свою BI.
- **Выгрузка XLSX/PDF** по периодам — для планёрок.

## Метрики успеха

| Метрика | Цель |
|---|---|
| Точность срабатывания правил (precision) | ≥ 0,9 после настройки на эталоне |
| Доля споров, закрытых в интерфейсе без переписки | ≥ 90 % |
| Время от отчёта до конкретного звонка-примера | ≤ 10 секунд (клик) |
| Влияние на метрику клиента (пример из пилота) | рост соблюдения скрипта на ≥ 5 п.п. за 2 месяца |

## Этапы

1. **MVP:** правила по словарям, отчёт «соблюдение скрипта», выгрузка.
2. **v1.1:** доказательства с таймкодами, очередь споров, дашборд по операторам.
3. **v1.2:** авто-коучинг — по каждому оператору подборка лучших/худших фрагментов недели
   с рекомендацией руководителю.

## Монетизация

Входит в «Бизнес» и выше — это ключевая причина перейти с «Старт» на «Бизнес»
(разница 40 000 ₽/мес). В пилоте фича продаётся первой: она даёт эффект, который можно
предъявить на планёрке через две недели.

## Почему этого нет у других

- **Модули телефонии:** чек-листы без доказательств и без разрешения споров.
- **SaaS для продаж:** LLM-оценка диалогов есть, но без привязки «правило → цитата → таймкод»
  и без контура оспаривания.
- **API-конструкторы:** контроль скрипта — задача клиента.
- **Enterprise:** умеют, но это отдельный модуль внутри проекта на миллионы.
