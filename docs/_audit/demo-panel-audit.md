| Уровень | Значение |

### 2.1. `demo/build/`: интерфейс показывает одно значение, справка — другое

| Где | Текст |
|---|---|
| Бейдж «горячее окно» | `горячее окно 3650 дн. · с 2016-10-30` |
| Метрика «горячее окно» | `3650 дн.` |
| `title` у ссылки-термина | `Сколько последних дней лежит в быстром слое; сейчас 90.` |
| Термин в справке | `Горячее окно — Сколько последних дней лежит в быстром слое; сейчас 90.` |

Пользователь видит **3650 дней** (≈10 лет), а подсказка и справка говорят **90 дней**.
Это прямое противоречие внутри одной страницы — самый заметный дефект `demo/build/`.

Значение `3650` само по себе **непротиворечиво**: `2016-10-30 + 3650 дней = 2026-10-28`,
то есть снимок ровно десятилетней давности — как и заявлено в «архиве (полный снапшот)».
Устаревшее значение — именно **«сейчас 90»**.

**Где в коде:** `docs/demo/build/index.html`, строка 94 (весь файл — одна строка):
- `горячее окно 3650 дн.` — 3 вхождения (бейдж ×2 в разметке + метрика),
- `сейчас 90` — 2 вхождения на этой странице (`title` атрибута + текст термина в справке);
- ещё **5 вхождений** того же текста в других файлах демо:
  `docs/demo/glossary/index.html` (2 — карточка термина `#term-hot-window` и список терминов),
  `docs/demo/learn-reports/index.html` (2), `docs/demo/glossary-search/index.html` (1).

То есть рассинхрон разошёлся по всему демо, а не только по странице сборки.

**Почему так вышло:** значение окна, вероятно, подставлялось в шаблон из конфигурации
(`hot_window_days`), а справочный текст про «сейчас 90» остался захардкоженным в HTML.
Демо-генератор печатает число в одном месте и текст в другом — нет единого источника.

**Как чинить:** вынести одно значение в шаблон и подставлять в оба места, например:

```html
<!-- было -->
<span class="badge">горячее окно 3650 дн. · с 2016-10-30</span>
<a class="term-ref" href="./#docs" title="Сколько последних дней лежит в быстром слое; сейчас 90.">

<!-- стало: число и текст из одной переменной hot_window_days -->
<span class="badge">горячее окно {{ hot_window_days }} дн. · с {{ hot_window_from }}</span>
<a class="term-ref" href="./#docs" title="Сколько последних дней лежит в быстром слое; сейчас {{ hot_window_days }}.">
```

**Осторожно (правила репозитория):** `3650` и `90` — числа, попадающие в интерфейс. По `AGENTS.md`
цифры нельзя «поправлять на глаз»: нужно взять утверждённое значение из закрытого контура.
Если канон говорит «90 дней», то правится бейдж и метрика, а не справка. Если канон — «3650»,
то правится текст справки. **Решение принимает владелец цифр, не аудит.**

### 2.2. «Отставание от источника» не соответствует собственным же `as_of` и `watermark` (52 страницы)

В блоке «Снимок» каждой страницы панели:

```
as_of:    2026-10-28T12:00:00+03:00      →  09:00 UTC
watermark: 2026-10-28T09:00:00.000000Z    →  09:00 UTC
отставание от источника: 11 ч
```

`as_of` и `watermark` указывают на **один и тот же момент** (12:00+03:00 = 09:00Z), поэтому
отставание равно **0 ч**, а в интерфейсе показано **11 ч** — на 52 страницах (53 вхождения
«11 ч», 6 вхождений «—»).

Это ошибка **логики/шаблона**, а не опечатка в одном файле: одно и то же значение
«11 ч» зашито в разметку, хотя расчётные значения (as_of, watermark) подставляются
переменными. По справке самой страницы: «Отставание в часах — сигнал, что каденция apply
сломалась» — демо показывает ложную тревогу.

**Как чинить:** считать отставание из `as_of` и `watermark` в шаблоне, а не хранить литерал:

```html
<!-- было -->
<span>отставание от источника: 11 ч</span>

<!-- стало -->
<span>отставание от источника: {{ lag_hours }} ч</span>
```

где `lag_hours = round((as_of - watermark).total_seconds() / 3600)`.
На текущем снимке это даст `0 ч`.

### 2.3. `demo/glossary-search/`: три ссылки ведут на несуществующие якоря

```
Связанные: <a href="#term-coverage">Coverage, %</a>
           <a href="#term-item-state">Y / N / NA / U</a>
           <a href="#term-bounds">Вилка lower…upper</a>
```

На странице поиска присутствует только одна карточка термина — `#term-resolved`.
Элементов `term-coverage`, `term-item-state`, `term-bounds` на этой странице **нет**
(они есть в полном словаре — `docs/demo/glossary/index.html`).

Итог: клик по «Связанные» на странице поиска **ничего не делает** (URL меняется на `#term-coverage`,
но браузер не находит цель и не прокручивает страницу).

**Исправление:** ссылки должны вести на словарь с якорем:

```html
<a href="../glossary/#term-coverage">Coverage, %</a>
<a href="../glossary/#term-item-state">Y / N / NA / U</a>
<a href="../glossary/#term-bounds">Вилка lower…upper</a>
```

Либо карточки связанных терминов должны рендериться на странице поиска (если это вёрстка
результатов поиска) — тогда нужны `id` на самих карточках.

### 2.4. `demo/exports-disabled/`: страница без `<main>`, без viewport и без общей оболочки

Страница целиком:

```html
<body>
  <aside class="demo-ribbon">…</aside>
  <h1>Экспорт отключён в демо</h1>
  <footer class="demo-footer">…</footer>
</body>
```

Найдено:
- **нет `<main>`** — контент вне семантического контейнера (единственная такая страница в демо);
- **нет `<meta name="viewport">`** — на мобильном рендерится в десктопном масштабе;
- **нет `<link rel="manifest">`** и favicon — страница выбивается из общей оболочки;
- `<h1>` лежит прямо в `<body>` без обёртки — стили `.v4-workspace` / `.v4-main` не применяются,
  страница выглядит «голой» по сравнению с остальными.

**Исправление:** привести страницу к общей оболочке `v4` (topbar + sidebar + `<main id="main">`)
либо как минимум добавить `viewport`, `lang` и обернуть заголовок в `<main>`.

### 3.1. 33 CSS-класса используются в разметке, но не имеют ни одного правила

Это **системная проблема вёрстки демо**, а не ошибка отдельной страницы: в разметке есть классы
`freshness`, `snap`, `snap-body`, `snap-signature`, `term-ref`, `docs-lead`, `v4-help`,
`v4-method-data`, `action-card`, `action-grid`, `fresh-block`, `chip-reset`, `chip-x`,
`toolbar-label`, `rail-views`, `view-save`, `current`, `time-availability`, `stage`,
`stage-name`, `transcript`, `report-controls`, `report-heading`, `report-sort`, `stage-row`,
`chips-empty`, `decision`, `decision-cell`, `finding-row`, `glossary-grid`, `term-careful`,
`data-note`, `v4-operator-filters`.

Проверено напрямую: в `<style>` этих страниц нет ни `.freshness`, ни `.snap`, ни `.term-ref`,
ни `.current` (для сравнения, `.v4-footer` и `.tool-chip` — есть). Следствия:

- блок «Свежесть и сборка» (`fresh-block` / `freshness`) на `demo/build/` **никак не оформлен**:
  `.freshness` — это `<div>` с `<strong>` и пятью `<span>`, а правил для них нет, поэтому все
  элементы инлайновые и строка «данные на 28.10 12:00 · применено: … · отставание … · горячее
  окно … · архив …» выводится **одной сплошной строкой** без разделителей, карточки и рамки;
  (правило `.rail-fresh` в CSS есть, но применяется только к футеру справки, не к этому блоку);
- карточки действий (`action-grid` / `action-card`) — сетка и рамки не заданы, карточки слипаются;
- сноска-ссылка `term-ref` не выделяется из обычного текста (в HTML она должна выглядеть как
  терминологическая сноска);
- таблица подписи снимка (`snap-signature`) — без рамки/шапки, а её `<caption>` без правил
  теряется;
- чипы активных фильтров (`chip-reset`, `chip-x`), сортировка (`report-sort`), заголовки
  отчётов (`report-heading`, `report-controls`) — без оформления.

**Это и есть наиболее вероятная причина того, что страница «выглядит не так»:** разметка
сгенерирована под CSS-контракт v4, а соответствующие правила в общий CSS-блок не попали
(потерян кусок таблицы стилей при сборке/выкатке демо).

**Как чинить:** восстановить недостающие правила в общем `<style>` (он дублируется во всех 60
страницах — значит, правится в генераторе, а не вручную в 60 файлах) либо удалить из разметки
неиспользуемые классы, если оформление не предполагалось.

### 3.2. `aria-current="page"` стоит у трёх ссылок одновременно (52 страницы)

Например, на `demo/build/`:

```html
<a href="./" aria-current="page">07 Сборка</a>          <!-- активный пункт меню — корректно -->
<a href="./#docs" aria-current="page">Как читать</a>    <!-- вкладка справки -->
<a href="./#docs" aria-current="page">Термины</a>      <!-- вкладка справки -->
```

`aria-current` должен быть **у одного** элемента. Сейчас скринридер получает три «текущих»
пункта. Кроме того, все три вкладки справки ведут на **один и тот же** `#docs` — вкладки не
работают как вкладки.

**Как чинить:** оставить `aria-current="page"` только у активного пункта бокового меню,
а вкладкам справки дать отдельные якоря (`#docs-read`, `#docs-terms`, `#docs-next`) и
использовать `aria-selected`/`role="tab"` либо просто убрать `aria-current` с неактивных вкладок.

### 3.3. `<button>` внутри `<form>` без атрибута `type` (45 страниц, 118 кнопок)

```html
<form method="post" action="#" aria-disabled="true" data-demo-post="disabled">
  <input type="hidden" name="csrf_token" … disabled>
  <button disabled>Применить свежее</button>
</form>
```

По умолчанию `<button>` внутри формы — это `type="submit"`. Сейчас все эти кнопки `disabled`,
поэтому немедленного вреда нет, но это **мина**: как только кнопку включат (или скрипт снимет
`disabled`), клик отправит форму на `action="#"`, то есть перезагрузит страницу с `#` в URL.
В `findings/index.html` таких кнопок 32, в `findings-conflict/index.html` — 8.

**Как чинить:** проставить `type="submit"` (или `type="button"` для не-отправляющих) во всех
кнопках внутри форм.

### 3.4. Служебный блок справки помечен как `<footer>` и лежит в колонке контента (58 страниц)

Разметка на всех 58 страницах панели:

```html
<div class="v4-workspace">
  <main class="v4-main" id="main" tabindex="-1">
    …
  </main>
  <footer class="v4-footer">   <!-- блочная справка, термины, снимок -->
    …
  </footer>
</div>
```

Формально `<footer>` не внутри `<main>` (он — сосед), но:
- он **внутри `<div class="v4-workspace">`**, который в сетке `grid-template-columns: 224px 1fr`
  является областью контента, поэтому нижний колонтитул зажат в колонку 1080 px;
- семантически «Справка и термины» + «Методика и данные» + «Снимок» — это содержимое страницы,
  а не site-footer; site-footer (`demo-footer`) и так есть отдельным элементом ниже;
- из-за этого `<footer>` в разметке **встречается дважды**, и инструменты, считающие «один footer
  на страницу», дают ложные срабатывания.

**Как чинить:** переименовать внутренний блок в `<section class="v4-help">` (или вынести его
за пределы `v4-workspace` на всю ширину), чтобы `footer` остался только site-footer.

### 3.5. SVG: атрибут `viewbox` вместо `viewBox` (59 страниц, 59 вхождений)

```html
<svg … viewbox="0 0 32 32">   <!-- было -->
<svg … viewBox="0 0 24 24">   <!-- корректно в остальных местах -->
```

Рендер **не ломается**: HTML-парсер сам приводит `viewbox` → `viewBox` (SVG attribute
adjustment table в спецификации HTML). Но код не соответствует канону SVG, а валидаторы
(и части инструментов, например some XML-парсеры) это отмечают.

**Как чинить:** `viewbox="0 0 32 32"` → `viewBox="0 0 32 32"` в генераторе (одно место правки
на все страницы).

### 3.6. Активный фильтр не выделен: класс `current` без правила CSS (35 страниц)

Разметка чипов активных фильтров:

```html
<span class="tool-chip current">…</span>   <!-- активный фильтр -->
<span class="tool-chip">…</span>           <!-- обычный фильтр -->
```

В CSS есть `.badge,.chip,.tool-chip{…}` — но правила `.current` **нет** (проверено по всем
страницам: строка `.current` в CSS-блоке отсутствует). В итоге активный фильтр выглядит
**точно так же**, как неактивный: нет заливки, рамки акцента, другого цвета текста.
Пользователь не может считывать состояние фильтра визуально.

**Как чинить:** добавить правило, например:

```css
.tool-chip.current{background:var(--accent);color:var(--on-accent);border-color:var(--accent)}
```

### 7.4. Инструменты и CI

- `tools/demo-html-audit.py` — структурный аудит демо (баланс тегов, дубли `id`, битые `#fragment`,
  `<main>`/`<h1>`, доступные имена полей и ссылок, классы без CSS, регистр SVG-атрибутов,
  внутренние ссылки, **согласованность данных** `as_of − watermark` и «горячее окно»).
- `tools/fix-demo-audit.py` — идемпотентный скрипт правок; переписывает страницы и манифест.
- `tools/format-demo-html.py` — форматтер HTML демо-панели: один элемент — одна строка,
  вложенность видна по отступам. Собственная реализация вместо `prettier`, потому что
  `prettier` вставляет пробелы между соседними инлайновыми элементами, а в этих
  страницах такие стыки намеренно плотные (например «вымышлены» + `<a>fonotext.ru</a>`) —
  это изменило бы вёрстку. Форматтер:
  - не добавляет и не убирает пробелы между элементами (текст сохраняется дословно);
  - не трогает содержимое `<style>` и `<script>` (CSS и JS остаются байт-в-байт);
  - не переносит атрибуты инлайновых элементов (перенос добавил бы пробел в текст);
  - проверяет результат: если видимый текст изменился — файл не перезаписывается.
- `.github/workflows/ci.yml` — job `demo-audit` (был `continue-on-error`, теперь **блокирующий**):
  1. `demo-html-audit.py` должен дать 0 замечаний;
  2. `fix-demo-audit.py` не должен ничего менять — иначе файлы разошлись с эталоном;
  3. `format-demo-html.py` не должен ничего менять — иначе разметка разошлась с форматом.
